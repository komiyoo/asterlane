# 身份服务与管理员登录

设计见 [开源版与 SaaS 双形态 · 身份服务](../../../architecture/open-source-and-saas.md#身份服务)，[^saas] 范围与准出见 [Roadmap · Phase 12](../../../product/roadmap.md#phase-12身份服务)。[^roadmap]

**开工条件**：维护者确认身份服务放在本仓库、以 MIT 发布（[代码与许可证边界](../../../architecture/open-source-and-saas.md#代码与许可证边界) 的待确认项）。如果改为私有，本计划移到私有仓库，公开仓库只保留 PR2 的 JWT 校验与 PR3 的角色检查，开源版继续只用 admin token。

## Context

管理面现在只有 admin token：`src/admin/auth.rs` 按 token 摘要找到 admin key ID，以 `AdminKeyId` 注入请求；审计（`record_audit`）只记 `admin_key_id`；所有持有 token 的人权限相同。SaaS 需要账号登录、组织、成员与角色，开源版希望能选用同一套。

维护者已选定 Better Auth 独立服务（Bun + Hono），Rust 侧只校验它签发的 JWT。2026-10-10 查阅的事实：JWT 插件经 `/api/auth/token` 发 JWT、`/api/auth/jwks` 公开公钥，默认 15 分钟过期、EdDSA（Ed25519）签名，密钥轮换默认关闭。[^ba-jwt]

## Approach

先在身份服务里把登录、组织和 JWT 跑通（PR1），再让 Rust 接受 JWT（PR2）和按角色授权（PR3），最后改审计、控制台和部署（PR4、PR5）。admin token 全程照旧可用，开源版默认仍用它。

控制台与身份服务同源：控制台 Nginx 把 `/api/auth/*` 转给身份服务，和现在把 `/admin/*` 转给网关一样。登录会话是身份服务的 httpOnly cookie；控制台用它向 `/api/auth/token` 换短期 JWT，JWT 只放在内存，调用 `/admin/*` 时放进 `Authorization: Bearer`。admin API 仍然只认请求头，不认 cookie，不引入 CSRF 面，也不开 CORS。

## Files

- `identity/`（新增）— Bun + Hono + Better Auth 服务、Dockerfile、README（固定版本与命令，写法同 `web/README.md`）。
- `.github/workflows/identity.yml`（新增）、`justfile` — 身份服务的检查与构建，不进入 Cargo 构建。
- `src/admin/auth.rs`、`src/admin/mod.rs`、`src/config/` — JWT 校验、管理员身份、角色检查与配置节。
- `src/admin/{crud,mcp,tokens,metadata,defaults,oauth}.rs`、`src/admin/types/` — handler 改用管理员身份，审计带操作人。
- `tests/it/`（新增 `admin_jwt.rs`）— JWT 与角色的集成测试。
- `web/src/app/login-page.tsx`、`web/src/api/`、`web/src/features/audit/`、`web/deploy/nginx.conf.template` — 账号登录、JWT 刷新、审计操作人、`/api/auth` 转发。
- `compose.yaml` — 可选启用的身份服务。
- `docs/architecture/crate-selection.md`、`docs/runtime/config-schema.md`、`docs/admin/admin-console.md`、`docs/architecture/console-separation.md`、`docs/admin/deployment.md` — 依赖、配置、认证与部署说明。

## Reuse

- `require_admin` 中间件和 `AdminKeyId` 注入点：JWT 是同一入口的第二种凭据，不另挂一套路由。
- `wiremock`（已是 dev 依赖）在测试里提供 JWKS；测试密钥在测试内生成，不进仓库。
- 控制台现有的会话处理（401 清理、旧请求不清理新会话）和登录页；`web/deploy/nginx.conf.template` 现有的 `/admin` 转发写法。
- Better Auth 的 organization 插件（组织、成员、角色、邀请）[^ba-org] 与 JWT 插件，不自写。

## PR1 身份服务骨架

- [ ] 在 `identity/` 建 Bun + Hono 服务，挂 Better Auth：邮箱密码登录，社交登录先留配置位；organization 插件；JWT 插件。存储开源版用 SQLite，SaaS 用 Postgres，表由 Better Auth 的迁移命令生成。版本固定并写进 README。
- [ ] JWT 载荷带用户 ID、当前组织 ID 和该组织里的角色（用 JWT 插件定义载荷的选项，实施前对照文档核对选项名）；`iss`、`aud` 显式配置，不依赖默认的 BASE_URL。
- [ ] 开启密钥轮换并设宽限期，验证轮换后旧 JWT 在宽限期内仍能用 JWKS 验证。
- [ ] 身份服务不读任何上游凭据，也不调用网关的代理接口。

验收：本地起服务后，注册、登录、建组织、邀请成员走通；`/api/auth/jwks` 的公钥能验证 `/api/auth/token` 发出的 JWT。

## PR2 admin API 接受 JWT

- [ ] 先在 [Crate 选型矩阵](../../../architecture/crate-selection.md) 登记 JWT 校验库（候选 `jsonwebtoken`），核对 EdDSA、JWK 支持和它的加密后端是否与已有的 `ring` 重复。[^crates]
- [ ] 配置新增 `admin.jwt`：`issuer`、`audience`、`jwks_url`；开源版另有一个组织 ID，只有这个组织的 JWT 被接受，对应唯一的默认租户。字段写进 [Gateway Configuration Schema](../../../runtime/config-schema.md)，旧配置不变。
- [ ] `require_admin` 先按 admin token 摘要匹配，不中再按 JWT 校验：验签，校验 `iss`、`aud`、`exp`；JWKS 缓存在内存，遇到未知 `kid` 重新拉取并限制频率；身份服务不可用时，已缓存公钥能验证的 JWT 照常通过。
- [ ] `AdminKeyId` 改为管理员身份：admin key（ID）或用户（用户 ID、组织 ID、角色）。错误沿用 `auth.*` 码，信息可安全展示，不回显 token。
- [ ] 集成测试：合法 JWT、过期、错误 `aud`、错误签名、未知 `kid` 触发刷新、其他组织、admin token 仍可用。

验收：只配 admin token 的部署行为与响应不变；配了 `admin.jwt` 后两种凭据都能用。

## PR3 按角色区分只读与可写

- [ ] 每条 admin 路由声明需要的角色，不按 HTTP 方法推断（调试调用是 POST 但有副作用，`config/validate` 只读）。organization 插件的 owner、admin 可写，member 只读；admin token 等同可写。
- [ ] 角色不足返回固定的 403 错误码，写进 [错误模型](../../../architecture/error-model.md)。
- [ ] 测试覆盖每条写路由对只读角色都返回 403。

验收：两个不同角色的用户各自登录，权限按角色生效（Phase 12 准出第一条）。

## PR4 审计记录操作人

- [ ] 审计 `details` 在 JWT 登录时记用户 ID 与组织 ID；admin token 登录时照旧记 `admin_key_id`。新字段可选，旧记录不迁移。
- [ ] 控制台审计页显示操作人；[Admin Console · 安全红线](../../../admin/admin-console.md#安全红线) 的审计字段同步。

验收：同一操作分别用 admin token 和账号执行，审计里能区分是谁。

## PR5 控制台账号登录与部署

- [ ] 登录页提供 admin token 与账号两种方式；没有部署身份服务时只显示 admin token。JWT 只放内存，过期前用会话 cookie 刷新，401 时刷新一次再失败才回登录页。只读角色在界面上隐藏或禁用写操作，以服务端 403 为准。
- [ ] `web/deploy/nginx.conf.template` 增加 `/api/auth/*` 转发，CSP 不变（仍是同源）。
- [ ] `compose.yaml` 以 profile 方式可选启用身份服务；[线上部署](../../../admin/deployment.md) 与 [控制台与网关分离架构 · 生产入口](../../../architecture/console-separation.md#生产入口) 同步。[^shell]
- [ ] e2e：账号登录、只读角色看不到写按钮、写接口返回 403；admin token 登录用例不变。

验收：Phase 12 准出三条全部成立，其中密钥轮换一条用 PR1 的轮换验证。

## Verification

Rust 改动跑 `just check`；控制台改动另跑 `just web e2e`；身份服务跑它自己的检查与测试。测试里的密钥、密码和 token 都是测试值，在测试内生成。完成后同步 [开源版与 SaaS 双形态 · 待定事项](../../../architecture/open-source-and-saas.md#待定事项) 里已经定下的项（JWT 校验库、吊销策略），再归档本计划。
