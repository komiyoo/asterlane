# 多租户数据面

设计见 [开源版与 SaaS 双形态 · 多租户数据面](../../../architecture/open-source-and-saas.md#多租户数据面)，[^saas] 范围与准出见 [Roadmap · Phase 13](../../../product/roadmap.md#phase-13多租户数据面)。[^roadmap]

依赖 [开源就绪与首次发布](w0-00-开源就绪与首次发布.md) 的 PR1（并发管理写入串行化）。与 [身份服务与管理员登录](w0-01-身份服务与管理员登录.md) 可以并行：本计划用 admin token 对应默认租户、测试里直接构造租户；身份服务合入后，JWT 里的组织 ID 映射到租户（PR3 最后一项）。

## Context

现状（证据见 [Roadmap · 横切：生产就绪](../../../product/roadmap.md#横切生产就绪)）：

- 存储只有 SQLite，`src/main.rs` 直接 `SqlitePool::connect`，`AppState.event_repo` 是具体的 SQLite 类型；仓储层已经按 trait 拆分（`src/store/repository/`）。
- 运行时配置是一份全局内存快照，启动时把 YAML 与数据库合并（同 id YAML 胜，见 [配置持久化闭环](../../../runtime/key-credentials-and-persistence.md#k2-配置持久化闭环)）。[^persistence]
- 限流计数、配额、key pool 冷却与 result cache 都在进程内。
- 没有租户概念；上游凭据可以是 `secret://env` 和 `secret://file`；出站请求不限制目标地址。

## Approach

按「先不改行为、再加租户」推进。PR1、PR2 只换存储和配置来源，开源版行为不变；PR3 引入租户标识，是改动最大的一步；PR4–PR7 在租户之上补共享状态、凭据、出站与运营能力。每个 PR 都保持单机 SQLite 可用，它仍是开源版默认。

开工前定下这几项，写进 [开源版与 SaaS 双形态 · 待定事项](../../../architecture/open-source-and-saas.md#待定事项)：租户 ID 的形式（与身份服务的组织 ID 一一对应）；身份服务与网关是否共用 Postgres 实例；Valkey / Redis 客户端 crate；KMS 选型（云 KMS 或 Vault Transit）。

## Files

- `src/store/`、`migrations/`（Postgres 迁移另放目录）、`src/main.rs` — Postgres 后端、按 URL scheme 选择、仓储改为 trait 对象。
- `src/http/state.rs`、`src/admin/`、`src/store/config_merge.rs` — 配置以数据库为准与版本号重载。
- `src/config/`、`src/catalog/`、`src/policy.rs`、`src/gateway_auth.rs`、`src/observability/`、`src/limits/`、`src/keys/`、`src/shaping.rs` — 租户标识与按租户的状态。
- `src/secrets/`、`src/mcp/oauth/` — 租户凭据的信封加密。
- `src/proxy/`、`src/mcp/peer/`、`src/mcp/oauth/` — 出站请求的地址校验。
- `tests/it/`（新增 `tenant_isolation.rs` 等）— 跨租户回归测试；Postgres 测试在 CI 用 service 容器，本机没有 Postgres 时 `#[ignore]`。

## Reuse

- `src/store/repository/` 现有的 trait：Postgres 实现同一组 trait，不新建第二套接口。
- 上游 OAuth 凭据现有的 ChaCha20-Poly1305 加密存储（[上游 OAuth 凭据](../../../runtime/key-credentials-and-persistence.md#上游-oauth-凭据)）：换成按租户的数据密钥即可沿用。
- 开源就绪计划 PR1 的管理写锁与 `swap_config_and_catalog`：单进程内的串行化保留，跨副本由数据库事务加版本号补上。
- `sqlx` 已支持 Postgres，只加 feature，不换库。

## PR1 Postgres 后端

2026-10-11 维护者决定暂缓：存储先用 SQLite，下面各项不做，其他 PR 在 SQLite 上推进。需要多副本时再恢复。

- [-] `sqlx` 开启 `postgres` feature，在 [Crate 选型矩阵](../../../architecture/crate-selection.md) 记录。[^crates] Postgres 迁移单独一个目录，两套迁移覆盖同样的表。
- [-] `AppState.event_repo` 改为 trait 对象；Postgres 实现 `src/store/repository/` 的全部 trait。
- [-] `serve --database-url` 按 scheme（`sqlite:`、`postgres:`）选后端；[运行网关](../../../admin/running.md) 与 [Gateway Configuration Schema](../../../runtime/config-schema.md) 同步。
- [-] 存储层测试对两个后端各跑一遍；CI 起 Postgres service 容器。

验收：同一组集成测试在 SQLite 与 Postgres 上都通过；不指定 Postgres 时行为与现在相同。

## PR2 配置以数据库为准

- [ ] 增加配置版本号：每次管理写入在一个数据库事务里写配置并递增版本号，提交成功才替换内存快照。
- [ ] 其他副本发现版本号变化后重新加载（Postgres 用 `LISTEN/NOTIFY` 加定期检查兜底；SQLite 单进程不需要）。
- [ ] SaaS 模式下配置只来自数据库，YAML 只用于导入导出；开源版保持现在的「YAML 加数据库合并」。两种模式的差别写进 [后向兼容策略](../../../architecture/compatibility-policy.md)。[^compat]

验收：两个副本连同一个 Postgres，在 A 上写入后 B 在一个检查周期内看到；并发写入不丢失。

## PR3 租户标识贯穿

- [ ] 定义 `TenantId` 类型；配置、目录、请求事件、用量、审计、安全事件、工具介绍与默认参数、上游 OAuth 凭据都带租户。迁移把已有数据归到默认租户。
- [ ] 仓储方法必须传入租户，类型上无法省略；Postgres 行级安全作为可选的第二道防线。
- [ ] gateway key 属于一个租户：`/mcp` 与 `/v1/*` 只看得到这个租户的工具。canonical 名在租户内唯一，不同租户可以同名。
- [ ] admin API 的租户来自管理员身份：admin token 对应默认租户；身份服务合入后，JWT 的组织 ID 映射到租户。
- [ ] 新增跨租户回归测试：一个租户的 admin API、事件、用量、目录和错误信息里都不出现另一个租户的数据。

验收：Phase 13 准出第一条成立。

## PR4 共享状态

- [ ] 在 [Crate 选型矩阵](../../../architecture/crate-selection.md) 登记 Valkey / Redis 客户端。限流计数、配额、key pool 冷却与 result cache 增加共享后端，默认仍是进程内。
- [ ] 限流算法在共享后端上怎样实现（GCRA 脚本或其他做法）先查成熟实现，写进 [限流维度设计](../../../architecture/rate-limit-dimensions.md) 或新的概念文档，再动代码。
- [ ] 共享后端不可用时的行为（拒绝还是退回进程内）要明确，写进文档并有测试。

验收：两副本部署下 per-key 配额与限流全局一致（Phase 13 准出第二条）。

## PR5 租户上游凭据

- [ ] SaaS 模式下租户配置拒绝 `secret://env` 与 `secret://file`，返回可安全展示的错误。
- [ ] 每个租户一把数据密钥，由 KMS 主密钥加密；租户的上游凭据与上游 OAuth 凭据用它加密后存数据库。密钥轮换与解密失败的处理写进 [配置持久化闭环](../../../runtime/key-credentials-and-persistence.md#上游-oauth-凭据) 一类的概念文档。
- [ ] 上游 OAuth 在 SaaS 下按租户各自授权一次。

验收：租户凭据在数据库里只有密文；换一个租户的数据密钥解不开另一个租户的凭据。

## PR6 出站请求防 SSRF

- [ ] HTTP 上游、MCP 上游连接和上游 OAuth 的元数据与 token 请求统一走同一个地址校验：拒绝回环、私网、链路本地和云元数据地址；DNS 解析后校验并固定连接这个 IP；重定向逐跳校验。优先用 `reqwest` 的自定义解析器挂进现有客户端，确认 rmcp 的传输与 OAuth 请求也用这个客户端。
- [ ] SaaS 默认开启，开源版默认关闭并提供开关。
- [ ] 测试覆盖各类地址、DNS 指向内网和重定向到内网。

验收：SaaS 模式下指向内网或云元数据地址的上游一律失败，错误可安全展示。

## PR7 租户限额、删除与导出

- [ ] 每租户的资源数、MCP 服务数、gateway key 数、请求速率、事件保留期和上游连接数可配置；具体套餐在私有仓库。
- [ ] 删除租户时清除配置、凭据、事件与缓存；导出配置 YAML 与事件。

验收：超出限额的写入被拒绝；删除后数据库与共享后端里没有该租户的数据。

## Verification

每个 PR 跑 `just check`；Postgres 与共享后端的测试在 CI 的 service 容器里跑。跨租户回归测试是准出的硬条件，之后每个涉及数据访问的改动都要保持它通过。完成后对照 [Roadmap · Phase 13](../../../product/roadmap.md#phase-13多租户数据面) 的准出确认，再归档本计划。
