# 控制台应用外壳与只读页面

应用边界见 [前端状态与安全](../../../architecture/console-separation.md#前端状态与安全)、[页面范围](../../../architecture/console-separation.md#页面范围) 与 [单一真实源](../../../architecture/console-separation.md#单一真实源)。[^arch] 业务字段以 [页面地图](../../../admin/admin-console.md#页面地图与-api-缺口) 为准。[^console]

## Context

前置计划已经分别提供 Rust schema 和独立前端工程。本阶段负责将它们接起来，建立后续管理页面可直接消费的 API、认证和导航基础。

## Approach

先完成生成类型与统一请求，再实现认证和路由，最后迁移总览、用量、密钥池、事件、安全事件、审计、配置七个页面。事件的“存为默认参数”由工具调试计划接入。资源、代理密钥、MCP、工具的四个页面入口暂时明确显示待迁移状态，后续计划替换各自模块，不争改路由表。

## Files

- `web/scripts/generate-api-types.ts`、`web/src/api/{index,client}.ts`、`web/src/api/generated/admin.d.ts` — 生成与请求入口；按域增加调用文件。
- `web/src/app/`、`web/src/components/` — 认证、布局、11 条路由和共享反馈组件。
- `web/src/features/{overview,usage,key-pools,events,security,audit,config}/` — 七个只读业务模块；其他四个目录只有明确的阶段占位入口。
- `web/tests/`、`web/e2e/`、`web/package.json` — 请求竞态、认证和读路径回归；此时加入类型生成器开发依赖。
- [`justfile`](../../../../justfile)、[`.github/workflows/ci.yml`](../../../../.github/workflows/ci.yml)、`.github/workflows/web.yml`、[`scripts/setup_worktree.py`](../../../../scripts/setup_worktree.py) — 统一检查与初始化，文档同步到 README、开发流程、Worktree 流程和脚本索引。

## Reuse

- [`src/admin/ui/core.js`](../../../../src/admin/ui/core.js) 的 `api`、`apiWrite`、`fmtCell` 和现有 token 存储语义 — 迁移行为，不搬 DOM/HTML 拼装。
- [`src/admin/ui/app.js`](../../../../src/admin/ui/app.js) 的页面注册与刷新行为 — 形成声明式路由和可发现的刷新入口。
- `tabs/events.js` 的查询参数与 cursor、`tabs/audit.js` 的 details 展示、`tabs/config.js` 的 YAML 下载 — 保持现有接口形状。
- 前置计划的 Rust DTO/schema 和 Vite+ 配置 — 不在页面手写响应 interface。

## PR1 类型生成与请求

- [ ] 从提交的 `schemas/admin.json` 生成单个 `admin.d.ts`，标记生成来源；增加仅比较不覆写的检查模式，生成结果再经项目格式工具规范化。
- [ ] 建立类型化 API 调用和统一安全错误处理，分别支持 JSON、204 和 YAML；使用 AbortController 和会话标识隔离旧请求，写请求不自动重试。
- [ ] 新增 `just api-types`、`just api-types-check`：仓库入口串联 Rust/schema/TS；`web/` 内生成命令只读提交的 schema，前端构建不调用 Cargo。

验收：故意改动 DTO/schema/生成类型的任一环都能被差异检查发现，恢复后检查通过；动态 JSON 值保持合法的递归 JSON 类型。

## PR2 认证与路由

- [ ] 实现手输 token、恢复当前标签页会话、退出与 401 处理；旧请求的失败不得清理新会话，断网不能伪装成认证失败。
- [ ] 注册全部 11 条架构指定路由、导航与刷新；未迁移页面显式占位，同时在 API 统一入口预留各域模块导出，后续计划只填充自己的 feature/API 文件。登录引导不能误显示敏感数据。
- [ ] 建立通用加载、空态、错误、表单提示与确认组件，复用 Kumo；检查焦点、label、键盘、亮暗主题与窄屏布局。

## PR3 只读页面与仓库检查

- [ ] 迁移总览、用量、密钥池、事件、安全事件、审计、配置七页；时间和计数遵守实际 API 字段，局部失败可见且能重试。
- [ ] 保持事件时间游标独立于展示排序；limit 查询结果标明范围，安全事件与审计不虚构服务端总页数。导出成功释放 object URL。
- [ ] 补“先慢后快”查询、快速切页、换 token 后旧 401、204、代理非 JSON 错误与 YAML 下载的回归；用真实本机网关走一次登录、读取和导出。
- [ ] 接入 `just web-check`、`web-test`、`web-build`、`web-e2e`，将静态检查、测试、构建与契约检查汇入 `just check`/CI；端到端另设任务。
- [ ] 更新 Worktree doctor/init，使完整研发环境可冻结安装前端依赖且每树隔离；保留纯 Cargo 的后端构建方式，同步 README 和脚本说明。

## Verification

执行 `just api-types-check`、`just check` 和本阶段的 `just web-e2e`。浏览器验证七页直达、刷新、后退、未登录、401、断网、快速切页、筛选与下载；使用隔离测试配置和 SQLite，不读用户运行配置。

本计划交付开发环境中的可用基础，不切换生产入口。后续计划的共享文件修改应集中在各自 API/feature 模块，公共 router 已在本计划固定入口。
