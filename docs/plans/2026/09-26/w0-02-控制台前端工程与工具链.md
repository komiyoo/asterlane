# 控制台前端工程与工具链

工具职责见 [前端工具链](../../../architecture/console-separation.md#前端工具链)，版本记录与依赖范围见 [控制台构建依赖](../../../architecture/crate-selection.md#控制台构建依赖目标待实施)。[^arch] [^deps]

## Context

仓库尚无 JS 工程和前端 CI。本计划仅建立可独立运行的前端基础，与 API 契约计划无前置关系，不使用临时手写 API 类型。

## Approach

在 `web/` 建立 React/TypeScript 应用，接入 Kumo、声明式路由与 Vite+。先验证组件样式和构建兼容，再固定版本。阶段交付为开发入口，不替换旧控制台或触发部署。

## Files

- `web/package.json`、`web/bun.lock`、`web/vite.config.ts`、`web/tsconfig*.json` — 唯一前端包、检查和构建配置。
- `web/index.html`、`web/src/main.tsx`、`web/src/app/`、`web/src/styles.css` — 最小可运行入口及 Kumo 样式。
- `web/README.md`、`web/.node-version`、必要的项目级工具版本配置 — 可复现安装、开发与检查说明。
- `.github/workflows/web.yml` — 独立前端 CI；本阶段不改已有 Rust jobs。
- [`.gitignore`](../../../../.gitignore)、[`.dockerignore`](../../../../.dockerignore) — 忽略依赖与构建产物，避免进入 Rust 镜像上下文。

## Reuse

- Vite+ 官方 React/TypeScript 接入方式与 Kumo 发布包 — 沿用标准配置，不手写 bundler 或复制 Kumo 源码。
- [`src/admin/ui/styles.css`](../../../../src/admin/ui/styles.css) — 参考现有信息密度、亮暗主题与状态语义，不复制 DOM 绑定逻辑。
- 现有 `.github/workflows/ci.yml` 的任务拆分方式 — 前端单独安装依赖和验证，后端仍可纯 Cargo 构建。

## PR1 固定工具链并验证组件

- [ ] 核实并固定 Vite+ CLI、项目 `vite-plus`、Node、Bun、React 与 Kumo 的兼容版本；在 `packageManager` 指定 Bun，提交唯一 `bun.lock`。
- [ ] 建立 TypeScript strict、React 插件与 Kumo 样式；使用发布包要求的 peer dependencies，说明任何额外依赖的具体用途。
- [ ] 验证一个含输入框与 Dialog 的开发页面，检查样式加载、键盘打开关闭与焦点恢复；本阶段只保留最小冒烟用例。

验收：不运行 Rust 也能开发、检查和打包前端；从锁文件安装的依赖与本机偶然可用的全局包无关。

## PR2 开发入口与质量检查

- [ ] 配置 `/admin` 开发代理，目标端口可通过开发环境变量覆盖；生产构建中不写管理员凭据或任意 API 地址。
- [ ] 明确启用 `lint.options.typeAware` 和 `typeCheck`，配置 Vitest 与独立 Playwright 入口；以一个故意制造的类型错误确认检查确实会失败，再撤回该错误。
- [ ] 新增前端 CI：冻结安装、`vp check`、`vp test --run`、`vp build`；保存构建产物供审阅，禁止此任务自动部署。
- [ ] 补前端 README、忽略规则与依赖选型的版本记录。仓库级 just/Worktree 接线交由依赖本计划的应用外壳计划统一完成，避免与 API 契约计划同时改公共入口。

## Verification

在 `web/` 执行 `vp install --frozen-lockfile`、`vp check`、`vp test --run`、`vp build`；用生产预览确认 JS/CSS 均来自构建目录，并实际走一次 Dialog 交互。

仓库根执行 `just check`。记录操作系统、固定版本和前端产物大小作为后续比较依据，不把构建速度或体积设为未经测量的承诺。
