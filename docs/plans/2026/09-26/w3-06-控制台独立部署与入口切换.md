# 控制台独立部署与入口切换

部署约定见 [生产入口](../../../architecture/console-separation.md#生产入口) 和 [本地组合部署](../../../architecture/console-separation.md#本地组合部署)，切换顺序与退出条件见 [迁移与发布](../../../architecture/console-separation.md#迁移与发布)、[验收标准](../../../architecture/console-separation.md#验收标准)。[^arch]

## Context

前置计划完成后，11 个页面已在独立开发入口可用，但 Rust 仍带旧 UI。本计划将新控制台变成独立交付物，完成真实反向代理下的验收，再删除旧页面服务。

## Approach

采用 Nginx 静态运行镜像与现有 Rust 镜像的两服务组合。先验证镜像和同源请求，再切换入口；旧 UI 的删除与公开启动提示同步完成。本计划准备部署产物和本地演练，不自动向远程环境发布。

## Files

- `web/Dockerfile`、`web/deploy/nginx.conf`、`web/.dockerignore` — 固定工具链构建、静态运行镜像与同源代理。
- [`compose.yaml`](../../../../compose.yaml)、[`Dockerfile`](../../../../Dockerfile)、[`.dockerignore`](../../../../.dockerignore) — 加入独立 web 服务并验证 Rust 镜像不依赖前端；现有数据卷保持兼容。
- [`src/admin/mod.rs`](../../../../src/admin/mod.rs)、[`src/admin/ui/`](../../../../src/admin/ui/)、[`src/http/mod.rs`](../../../../src/http/mod.rs)、[`src/main.rs`](../../../../src/main.rs) — 退役静态资源路由、旧根重定向和启动提示。
- `web/e2e/deployment.spec.ts`、部署冒烟脚本、[`justfile`](../../../../justfile)、`.github/workflows/web.yml` — 真实入口验证与独立构建产物。
- README、前端 README、相关架构/管理/工程文档与 `docs/log.md` — 更新实际入口、安装与升级说明。

## Reuse

- 现有 Rust `Dockerfile` 的非 root 用户和 `/healthz` 探活 — 后端不加入 JS 工具链。
- 现有 `compose.yaml` 的 gateway 配置和数据库卷 — 测试另用独立 project 和配置，不迁移或清空用户数据。
- 既有 Bearer 中间件、HTTP 边界与所有 API 路由 — Nginx 原样代理，禁止重新实现授权。
- 前置浏览器用例 — 切换 base URL 到真实静态入口执行，补代理与缓存行为。

## PR1 独立镜像与同源代理

- [ ] 构建 `web` 多阶段镜像，固定工具版本、冻结安装，最终镜像只留静态文件和 Nginx；根 Rust 镜像可在没有 web 产物的环境单独构建。
- [ ] 配置 `/admin/*` 原样代理，正确保留 Authorization、body、query、状态码和下载响应；SPA 回退仅用于页面，未知资源与 API 失败不变成 HTML。
- [ ] 配置 HTML 重新验证、hash 资源缓存、API 不缓存和页面安全头；从上版发布产物保留上一版 hash 静态资源并验证旧页面跨版本加载。
- [ ] Compose 加 web 服务和独立健康检查，默认控制台 3722、网关原有 3721 端口；内部网络访问 `gateway:3000`，不向前端构建或容器注入 admin token。

验收：控制台和网关可分别启动；前端容器健康与网关健康能单独判断，真实登录、POST/DELETE 和 YAML 下载均正常。

## PR2 全量验收与退役旧 UI

- [ ] 用隔离配置、数据库和本地上游替身，在 Nginx 入口运行全部 11 页及关键写操作验收；记录现有页面能力逐项对应结果，未通过不得删除旧 UI。
- [ ] 验证未登录/无效 token、浏览器刷新/后退、未知静态资源、API 404/503、断连、敏感 token 清理与实际审计；浏览器不能直接访问上游。
- [ ] 删除 `src/admin/ui/`、`console`、`ui_asset` 和手写 ASSETS，移除 Rust `/` 到 `/admin/ui` 的重定向；启动提示改为 admin API 信息。
- [ ] 新 Web 入口仅对 `/admin/ui`、`/admin/ui/` 做精确重定向；Rust 原始端口旧 UI 为 404，更新原 `admin_ui_page_public_and_html` 测试并覆盖网关端点继续可用。

## PR3 构建发布与回滚说明

- [ ] 在 CI 分别构建 Rust 与前端产物，增加契约漂移检查及部署冒烟；发布产物标明提交和工具版本，避免前后端隐式强制一起编译。
- [ ] 新增 `just web-deploy-smoke`，用独立 Compose project/测试卷演练启动、升级、前端回滚和上一版兼容组合回滚；清理仅限本测试新建资源。
- [ ] 更新根 README 的快速开始、端点与 Docker 用法，以及开发/Worktree/管理/架构文档；将已实现部分从目标描述改为现状，保留明确的旧入口迁移说明。
- [ ] 在全部验收通过后记录实际命令和结果，完成待办；按 plan-docs 流程先沉淀文档与时间线，再归档已完成计划。

## Verification

执行 `just check`、`just web-e2e`、`just web-deploy-smoke`，分别构建根 Rust 镜像和前端镜像。生产构建验收不能以 `vp dev` 的代理结果替代。仓库验证遵循 [Validation](../../../engineering/development-workflow.md#validation)。[^workflow]

如果本机无法运行容器，记录具体失败命令和原因，容器/切换待办保持未完成，不据此声称可以正式退役旧 UI。远程部署、推送镜像或修改现有生产数据须由用户另行授权。
